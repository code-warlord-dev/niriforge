# Безопасность и работа с конфигурацией

## Гарантии

1. **Никогда не пишем невалидный конфиг**  
   Перед заменой файлов обязательно запускается `niri validate` на временных копиях. При ошибке изменения не применяются.

2. **Atomic write**  
   Запись идёт во временный файл → fsync → rename. Получить half-written config.kdl невозможно.

3. **Автоматический бэкап**  
   Перед каждым успешным save создаётся timestamped backup всех затронутых файлов.

4. **Symlink-aware**  
   Если `config.kdl` — symlink (Home Manager, dotfiles), пишем в реальный target.

5. **Multi-file integrity**  
   Изменения пишутся только в те файлы, из которых пришёл соответствующий node. Чужие include (Noctalia, Dank и т.д.) не перезаписываются без необходимости.

6. **Preserve unknown**  
   Неизвестные блоки и комментарии сохраняются максимально возможно.

## Что делать пользователю при проблемах

- Если validate упал — смотри Validation panel, исправляй или откатывайся через Backup.
- Если конфиг "поехал" после GUI — восстанови последний auto-backup.
- Если используешь Home Manager — убедись, что symlink out-of-store (как в оригинальном NiriMod).

## Ограничения

- Идеальное сохранение formatting (пробелы, порядок ключей внутри node) не всегда возможно — приоритет у семантики и комментариев.
- При очень старых/экзотических конфигах возможен fallback в raw-режим.
